# Gateway и Ledger

Учебный проект: HTTP-шлюз и учёт расходов с бюджетами по категориям.
Два независимых сервиса работают на Go 1.22 или новее.
Каждый сервис имеет собственный `go.mod` и использует только стандартную
библиотеку. Команды ниже выполняются из корня репозитория.

## Структура

- `gateway/` — HTTP-сервер на порту 8080 и тесты обработчика.
- `ledger/` — транзакции и бюджеты в памяти, загрузка JSON, консольная демонстрация и тесты.
- `ledger/budgets.json` — начальные бюджеты демонстрации.
- [AGENTS.md](AGENTS.md) и `rules/` — правила разработки.

## Запуск Gateway

В первом терминале:

```sh
cd gateway
go run .
```

Сервис продолжает работать до остановки через `Ctrl+C`.
В другом терминале отправьте запрос:

```sh
curl -i http://localhost:8080/ping
```

Ожидается статус `HTTP/1.1 200 OK` и тело `pong` без завершающего перевода строки.
Другие методы для `/ping` возвращают `405 Method Not Allowed` с `Allow: GET`,
неизвестные пути — `404 Not Found`.

## Запуск Ledger

Во втором терминале из корня репозитория:

```sh
cd ledger
go run .
```

Запускайте Ledger из каталога `ledger/`: программа открывает `budgets.json`
относительно текущего рабочего каталога. Файл содержит начальные лимиты:

```json
[
  { "category": "еда", "limit": 5000 },
  { "category": "транспорт", "limit": 1000 }
]
```

`main` открывает файл через `os.Open`, передаёт `bufio.NewReader` в `LoadBudgets`
и закрывает файл после выполнения. `LoadBudgets` устанавливает проверенные
бюджеты через `SetBudget`. Это единственный источник начальных лимитов:
изменение файла меняет результат демонстрации.

При стандартном файле после сообщения `Ledger service started` программа
показывает пять добавленных транзакций и один отказ с причиной `budget exceeded`.
Расходы на еду 1500 и 2000 рублей принимаются; следующие 2000 рублей
отклоняются, поскольку общая сумма стала бы 5500. Затем 1500 рублей принимаются:
итог ровно 5000 разрешён. Расходы на транспорт 700 рублей и книги 950 рублей
также принимаются. Для книг бюджет не задан.

Итоговая часть вывода:

```text
Сохранено транзакций: 5
1 | 1500.00 руб. | еда | Продукты | 2026-11-06
2 | 2000.00 руб. | еда | Покупки на неделю | 2026-11-06
3 | 1500.00 руб. | еда | Обед | 2026-11-06
4 | 700.00 руб. | транспорт | Проездной | 2026-11-06
5 | 950.00 руб. | книги | Учебник Go | 2026-11-06
```

Отклонённый «Ужин» не попадает в список и не расходует ID. Ledger выводит историю
через `ListTransactions`, затем завершает работу. Транзакции хранятся только
в памяти; каждый запуск начинает новую историю. Gateway и Ledger запускаются
отдельно и не обмениваются данными; gRPC будет добавлен в следующих заданиях.

## Транзакции

`Transaction` содержит поля `ID int`, `Amount float64`, `Category string`,
`Description string`, `Date string`. Суммы заданы в рублях; в демонстрации даты
используют формат `YYYY-MM-DD` и хранятся как строки.

Хранилище — структура `Ledger` с собственным срезом `[]Transaction`.
Её нулевое значение также готово к использованию.

- `(*Ledger).AddTransaction(tx Transaction) error` проверяет непустую категорию
  и положительную конечную сумму. Ноль, отрицательные суммы, `NaN` и бесконечность
  отклоняются без изменения истории. Если бюджет задан, проверяется сумма всех
  принятых расходов категории вместе с новым. Превышение возвращает
  `ErrBudgetExceeded`, распознаваемую через `errors.Is`; при успехе — `nil`.
- Хранилище само назначает последовательные ID с 1, заменяя переданный ID.
  Отклонённая транзакция не расходует ID.
- `(*Ledger).ListTransactions() []Transaction` возвращает копию всех транзакций
  в порядке добавления. Изменение копии не затрагивает хранилище.

## Бюджеты и JSON

`Budget` содержит `Category string` и `Limit float64`. Бюджеты хранятся
в `map[string]Budget` по названию категории. Лимит фиксирован для всей истории
категории; периодов и автоматического сброса расходов нет.

`(*Ledger).SetBudget(b Budget)` добавляет или заменяет лимит. Для прямого вызова
передавайте непустую категорию и конечный неотрицательный лимит. Уже принятые
расходы сохраняются и учитываются при следующем добавлении. Если новый лимит
меньше накопленных расходов, история остаётся, но новые расходы отклоняются.
При нулевом лимите любые положительные расходы категории отклоняются.
Категория без бюджета не ограничена.

Поля сумм остаются `float64`. Для проверки лимита их кратчайшие десятичные
представления складываются точно через стандартный `math/big.Rat`: расходы
`0.10` и `0.20` принимаются при лимите `0.30`. Произвольного допуска на превышение
нет. Точность, уже потерянная до передачи значения в `float64`, не восстанавливается.

`(*Ledger).LoadBudgets(r io.Reader) error` принимает ровно один JSON-массив:

- `category` и `limit` обязательны. Пустая категория, отрицательный лимит,
  пропущенный `limit` и `null` вместо него считаются ошибкой; явный ноль допустим.
- Сначала проверяются весь массив и конец документа, затем бюджеты применяются
  через `SetBudget`. При ошибке бюджеты и транзакции остаются прежними.
- Повторная категория обновляет предыдущий лимит; последнее значение побеждает.
  Категории, отсутствующие в массиве, сохраняют существующие бюджеты.
- `[]` ничего не меняет. При запуске с пустым массивом бюджетов нет, поэтому
  все шесть демонстрационных транзакций принимаются.
- Ошибки чтения и разбора JSON возвращаются с контекстом и исходной причиной.
  `LoadBudgets` не закрывает переданный источник.

При ошибке открытия файла или загрузки Ledger сообщает причину и завершается
с ненулевым кодом, не запуская демонстрацию. Ошибки вывода также останавливают
выполнение. Ожидаемый отказ по бюджету выводится отдельно, после него обработка
остальных транзакций продолжается.

## Проверки

Из корня репозитория:

```sh
gofmt -l .
(cd gateway && go test ./... && go vet ./...)
(cd ledger && go test ./... && go vet ./...)
```

У `gofmt -l .` не должно быть вывода. Корневого `go.mod` нет, поэтому Go-проверки
выполняются отдельно в каждом модуле.

Тесты проверяют HTTP-ответы, сохранение полей и порядка транзакций, ID без пропусков
при отказе, копию истории, суммарные лимиты и точное равенство, независимость
категорий, обновление бюджета, загрузку JSON без частичных изменений,
ошибки чтения и парсинга, вывод демонстрации и ошибки записи. Файловые тесты
используют временные каталоги и не меняют рабочий `ledger/budgets.json`.
